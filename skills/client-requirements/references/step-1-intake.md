# 第 1 步 · 现场纪要

> 产物: `.req/intake.md` ｜ 过关: `gate.mjs check 1`

## 陪跑流程

1. 让用户把手上所有原始材料一次性给你：录音转写、聊天截图、会议笔记、客户发的表格单据。
2. 用 ① 整理成纪要。**原话不改写**，事实和推断分段，推断不准混进事实。
3. 让用户补"真实材料"：客户正在用的 Excel、纸质单据照片、现有系统截图。没有就列成第 4 步的 T1 问题"能否提供 X 样例"。
4. `gate check 1`。

## Prompt ① 原始材料 → 纪要

```
你是企业项目的需求调研员。下面是我拜访客户后的原始材料：
[粘贴录音转写 / 笔记 / 聊天记录]
按 .req/intake.md 模板整理，规则：
1. 「客户原话」只摘录原句，标说话人和角色，不改写、不总结。
2. 「事实」只放客户明确说的、我亲眼看到的，每条标出处。
3. 你推测出来的东西一律放「推断」，哪怕你很有把握。
4. 材料里提到但我没拿到的单据、表格、系统，列进「材料清单」并注明"未提供"。
不要提解决方案，不要写需求。
```

## 判据

- 原话 ≥3 条，每条有说话人。只有转述没有原话 = 回去再听一遍录音。
- 事实 ≥3 条，每条有"出处："。
- 真实材料 ≥1 项。一份真实单据胜过十句描述。
- 模判：「事实」段里有没有"应该、可能、估计、大概"这类推断词。

## 过关前自查

- 客户原话里，有没有一句是在描述"现在怎么干"？没有 = 下一步画不出 As-Is。
- 你记下的是客户的问题，还是客户自己想的方案？方案也要记，但要追问它背后的问题。
