# 第 7 步 · 组装 PRD

> 产物: `.req/prd.md` ｜ 过关: `gate.mjs check 7`

## 陪跑流程

1. 用 ① 把前 6 份产物组装成 PRD。**只组装，不新增需求**。发现缺的，回到对应步骤补，再组装。
2. 清理所有【需要确认】。T3 待定项移到「风险与待定」，写负责人和何时定。
3. 文档信息写版本号（从 v1.0 开始），之后每次改都记变更记录。
4. `gate check 7`。通过后：PRD 交工程层，验收用例交验收层，scope.md 作为合同附件。

## Prompt ① 组装

```
用下面 6 份产物组装 PRD，按 .req/prd.md 模板的章节输出：
<<注入 .req/intake.md>>
<<注入 .req/stakeholders.md>>
<<注入 .req/process.md>>
<<注入 .req/questions.md>>
<<注入 .req/requirements.md>>
<<注入 .req/scope.md>>
规则：
1. 只用产物里已有的内容，不新增需求、不改优先级、不改验收句。
2. 功能需求保留 F 编号、优先级、真实样例和验收。
3. 背景与目标里的目标要带数字，取自痛点量化。
4. 发现前后矛盾或缺失，不要自己补，列在最后告诉我回哪一步改。
```

## Prompt ② 开发视角预审

```
你是要接这个项目的技术负责人。读这份 PRD：<<注入 .req/prd.md>>
不要写代码。列出：
1. 你开工前还必须问的问题（只列答案会改变实现的）。
2. 你认为工作量被低估的地方。
3. 验收用例里你没法照着测的条目。
没有就说没有，不要凑数。
```

## 判据

- 十个章节齐全：文档信息、背景与目标、角色、现状与目标流程、功能需求、非功能需求、AI 效果、范围与验收、变更规则、风险与待定。
- 文档信息里版本已填。
- 整个 `.req/` 目录不再有【需要确认】；T2 的答案和出处全部清零，T3 只在「风险与待定」中保留负责人和决定时间。
- PRD 里没有 `{占位符}`。
- 模判：PRD 的 F 编号和 requirements.md 一致，没有新增或丢失。

## 过关前自查

- Prompt ② 的预审跑了吗？它问出的问题，要么回填，要么在「风险与待定」里写明。
