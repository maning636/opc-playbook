# 第 2 步 · 角色与诉求

> 产物: `.req/stakeholders.md` ｜ 过关: `gate.mjs check 2`

## 陪跑流程

1. 用 ① 从纪要里抽角色。企业项目至少有四类：**出钱的、使用的、审批的、对接 IT 的**。
2. 缺哪类就问用户"这个人是谁"，不知道就写进第 4 步 T1："谁负责 X"。
3. 每个角色写"最在意什么、最怕什么"。最怕什么往往决定项目能不能落地（使用者怕被考核、IT 怕担责、老板怕花钱没效果）。
4. 「是否见过」如实填。使用者一个都没见过，机判会拦截；先补访，或列入第 4 步 T1 后再继续。

## Prompt ① 纪要 → 角色表

```
基于纪要：<<注入 .req/intake.md>>
按 .req/stakeholders.md 模板列角色表。要求：
1. 类型只用：出钱 / 使用 / 审批 / 对接IT，可兼多类。
2. "最在意""最怕"要有纪要原话或事实支撑，没有支撑的标【需要确认】。
3. 找出角色之间互相冲突的诉求（例：老板要管控，员工怕被监控），写进「冲突」段并说明谁说了算。
4. 四类里缺哪类，单独列出来问我。
```

## 判据

- 四类角色都有人。缺"使用"= 这是老板的项目不是业务的项目，风险最高。
- 「冲突」段不为空。没有冲突也要写理由。
- 「拍板人」三项都填：需求拍板、验收签字、付款审批。

## 过关前自查

- 验收签字的人见过吗？没见过的人签字，最容易在验收时翻案。
