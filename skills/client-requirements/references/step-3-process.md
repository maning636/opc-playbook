# 第 3 步 · 现状流程

> 产物: `.req/process.md` ｜ 过关: `gate.mjs check 3`

## 陪跑流程

1. 先画 As-Is：客户**现在**怎么干，一步一行，写执行人、工具、耗时。不写你想怎么改。
2. 痛点必须量化：每天几次、每次多久、一个月错几单、损失多少钱。客户说"很麻烦"要追问"麻烦到什么程度"。
3. 再写 To-Be，和 As-Is 逐项对应，每步标【不变】【改】【新增】【取消】。自动化可以合并或取消步骤，To-Be 数量允许少于 As-Is。
4. 「不碰的部分」写清楚，它会直接变成第 6 步的"不含"。

## Prompt ① 纪要 + 角色 → As-Is

```
基于纪要：<<注入 .req/intake.md>>
和角色：<<注入 .req/stakeholders.md>>
画出客户现在的业务流程（As-Is），每步一行：步骤 ｜ 执行人 ｜ 工具 ｜ 耗时。
只写纪要里有依据的步骤；有断档的地方（不知道谁做、用什么做）标【需要确认】。
然后列痛点，每条带量化数字和出处；没有数字的痛点列成问题问我。
```

## Prompt ② As-Is → To-Be

```
基于现状流程：<<注入 .req/process.md>>
给出目标流程（To-Be），和 As-Is 逐步对应，每步标【不变】【改】【新增】【取消】。
原则：改动最少的方案优先；能用表格和现有系统解决的，不新做系统。
每个【改】【新增】说一句它解决了哪条痛点。
```

## 判据

- As-Is ≥3 步，每步有执行人。
- 痛点 ≥1 条，每条含数字。
- To-Be 每步都有变化标记，且至少一步不是【不变】。

## 过关前自查

- 让客户的使用者看 As-Is，他会不会说"不对，我们其实是这么干的"？
- To-Be 改动的步骤，执行人愿意改吗？（回看第 2 步"最怕什么"）
