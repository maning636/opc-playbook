# AB 实验与假设验证设计

实验的价值不在于"测出个结果"，而在于**用一个便宜的、可证伪的动作，
避免一个昂贵的、不可逆的决定**。

所以第一问永远不是"怎么设计 A/B 测试"，而是**"这个决定值不值得花这个成本去验证"**。

---

## 1. 先判断：这个事该不该做实验

### 三问筛选

| 问 | 不合格的样子 | 合格的样子 |
|---|---|---|
| 1. 这个决定**可逆**吗？ | 不可逆且重大（辞职、签约、迁移技术栈） | 可逆或成本可控 |
| 2. 两个选项**差别大到值得测**吗？ | 差别只有 5%，且方向基本确定 | 差别可能让结论反转 |
| 3. 你**真的会按结果行动**吗？ | "测完看看" | "A 赢就全量 B，否则停掉" |

**三问有两问答"否" → 不要做实验。** 直接决策 + 留观察窗口更省时间。
**第一问答"否"（不可逆）→ 不要做 A/B，做「小样本预演 + 专家评审 + 契约保护条款」。**

### 什么时候根本不需要 A/B

- 样本量根本不够（后面会算）→ 用 §6 的替代方案
- 改的是**内部流程**不是用户可见的东西 → 直接改，看结果
- 是**明显更好的方案**（修 bug、加日志）→ 直接上，不需要对照组

## 2. 可实验假设的格式

不合格的假设无法证伪，也无法决定行动：

- ❌ "用户喜欢这个功能"
- ❌ "新定价能提升收入"
- ❌ "这个落地页更好"

合格的假设必须包含 **对照、指标、阈值、动作**：

```
因为 [证据/观察]，
我认为 [对某人群] 改动 [X] 会让 [指标] 从 [基线] 变化到 [阈值]，
如果成立，我会 [具体动作]；
如果不成立，我会 [具体动作]。
```

例子：

> 因为 10 人访谈里 6 人提到"不知道怎么开始"，
> 我认为对**首次访问的独立开发者**把落地页首屏从产品介绍换成"3 分钟做出第一个动效"，
> 会让**付费转化率**从 1.8% 提升到 **≥3.0%**，
> 成立则全量替换并把它写进 `opc-100day-profit` 的 Day 1-30 主线；
> 不成立则保留原页面，转去做 `opc-niche-positioning` 重新确认 ICP。

**最后两行是关键。** 没有"不成立怎么办"的假设，不是实验，是许愿。

## 3. 实验骨架（写下来再动手）

```yaml
实验编号: EXP-2026-11-03-landing
假设: 见上（完整格式）
负责人: 我
开始日期: 2026-11-04
结束日期: 2026-11-18（预设，不许提前停）

对照组 A: 现有落地页（首屏=产品介绍）
实验组 B: 首屏=3 分钟做出第一个动效
分流方式: 访客级随机（按匿名用户 ID 哈希取模，保证同一人始终落在同一组）
排除项: 内部 IP、已付费用户、机器人 UA
样本量: 每组 1,200 访客（按 §4 计算）
主指标: 付费转化率（口径见 opc-metric-dictionary）
护栏指标: 落地页跳出率 < 65%（若破，立即停）
判定规则:
  - 显著（p < 0.05）且 B 转化率 ≥ 3.0%  → 全量 B
  - 不显著                                → 保留 A，记为"已排除"，不再重测
  - B 显著更差                            → 回滚，并查护栏指标
  - 提前 7 天就有显著差异                  → 不停，按原计划跑满（除非护栏破）
```

**"不显著就保留 A 并记为已排除"这一条一定要写。** 否则你会一个月后再测一遍。

## 4. 样本量：先算，再跑

**不要用"跑一周看看"的土办法。** 一人公司最容易浪费的就是样本量不够还硬跑。

### 最小可用算法

```
n（每组） ≈ 16 × p(1-p) / δ²        （粗略估计，p 是基线转化率，δ 是想检测的最小提升）
```

例子：基线转化率 p = 1.8%，想检测提升到 3.0%（δ = 1.2pp）：

```
n ≈ 16 × 0.018 × 0.982 / 0.012²
  ≈ 16 × 0.01768 / 0.000144
  ≈ 19,600（每组）
```

**注意这个数。** 一人公司往往拿不到这个流量 → 这时候**不该做 A/B**，该走 §6。

### 经验规则

| 每周访客量 | 能做什么 |
|---|---|
| < 500 | 别做 A/B。用 §6 的替代方案 |
| 500 ~ 5,000 | 只能测**大改动**（转化率变化 > 50%），且只测一个指标 |
| > 5,000 | 可以做常规 AB，但样本仍要算 |
| > 20,000 | 可以做多变量测试 |

### 算样本量的工具

- `https://www.evanmiller.org/ab-testing/calculator.html`（离线可跑）
- `growthguru.io/ab-test-calculator`
- 或直接看 §4 的粗略公式 + 留 20% 余量

**永远把最小可检测提升（MDE）写出来。**"我想看有没有提升"不是 MDE。

## 5. 七个失败模式（一人公司最常踩）

| 失败模式 | 表现 | 修法 |
|---|---|---|
| **偷看数据提前停** | 第 3 天"看起来有差异"就停 | 结束日期预设，不许改（除非护栏破） |
| **同时改多个变量** | 改了首屏文案也改了按钮颜色 | 单变量；多变量用因子实验 |
| **样本量不足硬跑** | 200 人跑 14 天，下结论 | 先算样本量，不够就换方案 |
| **不预先注册** | 跑完挑"看起来最好"的指标 | 事前写死主指标 + 判定规则 |
| **分流不均** | B 组访客质量本来就差 | 检查分流是否随机；按重要维度分层看 |
| **幸存者偏差** | 只统计完成注册的 | 分母必须是**所有分流到的访客** |
| **多重比较** | 看了 20 个指标挑显著的那个 | 只看 1 个主指标 + 少量护栏指标 |

## 6. 样本不够时的替代方案（按优先级）

```
① 前置访谈（10 人）           —— 最便宜，能证伪"有没有这个需求"
② 假门测试 fake door         —— 放"加入候补名单"按钮，数点击/留邮箱
③ 付费意向页                 —— 真报价页，收定金或"预约付费咨询"
④ 手工预售                   —— 亲自找 20 个目标客户谈
⑤ 前后对照（before/after）   —— 有历史基线时可用，但必须排除季节性
⑥ 分层测试                   —— 按 ICP 分层各跑各的，适合样本分散
⑦ 序贯检验                   —— 允许连续看，但用正确的统计方法
```

**一人公司的最优解几乎总是 ③ 付费意向页。**
真金白银的 99 块比 5000 次页面浏览更有说服力。

## 7. 实验台账

每次实验记一行，**结论必须归档**（否则半年后你会重做一个已经做过的实验）：

| 编号 | 日期 | 假设 | 变量 | 主指标 | 结果 | 结论 | 下一步 |
|---|---|---|---|---|---|---|---|
| EXP-2026-11-03 | 11-04 | 首屏换成"3分钟做出动效" | 首屏 | 付费转化率 | p=0.31 | 不显著，已排除 | 转 opc-niche-positioning 重定 ICP |

台账存在工作区（见 `agent-workspace-spec/01 篇` 的 `台账.md`）。

## 8. 哪个 OPC 阶段该做什么实验

| OPC 阶段 | 阶段问题 | 首选验证方式 | 不要做 |
|---|---|---|---|
| 赛道选择 | 有人要这个问题吗 | 10 人访谈 + 付费意向页 | A/B 落地页（还没到那步） |
| 价值主张 | 说对了吗 | 定价页 / 一句话复述测试 | A/B 多个文案 |
| MVP | 交付得出去吗 | 手工交付 3 单 | A/B 产品功能 |
| 转化闭环 | 漏在哪一环 | 逐环节埋点 + 前后对照 | 大规模 A/B |
| 获客增长 | 哪个渠道有效 | 分渠道对比 + 内容 A/B | 同时投 5 个渠道 |
| 经营体检 | 哪个环节最弱 | 指标字典 + 根因分析 | AB |
