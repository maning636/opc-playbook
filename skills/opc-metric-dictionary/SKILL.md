# 指标字典与口径纪律

指标不是"看板上的一行数字"，是**一个双方都同意的约定**：算什么、怎么算、算谁的、
什么时候算、谁负责、算出来多少算好。

没有口径的指标，比没有指标更危险 —— 它让人在错的基础上做决策。

---

## 1. 什么时候用这个 Skill

| 触发 | 典型话术 |
|---|---|
| 两个人算出的数不一样 | "我们上个月的转化率到底是多少？" |
| 要做看板 | "帮我把这些指标做成仪表盘" |
| 要定"什么算成功" | "这个阶段我该盯什么数？" |
| 指标定义模糊 | "增长"、"复购"、"健康"、"口碑好" |
| 要验收一个阶段 | "这个阶段的通过标准是什么数？" |
| 指标失真 | "用户涨了但收入没涨" |

**不适用**：SaaS 专属口径（NDR、MRR、Rule of 40、CAC 回收期、Logo Churn）
→ 本机已装 `Product-Manager-Skills` 插件的 `saas-revenue-growth-metrics` /
`saas-economics-efficiency-metrics` / `finance-metrics-quickref`，
**直接引用，不要重复建设**。本 Skill 只做**通用（尤其一人公司/服务型）**口径。

## 2. 指标分层：不同层级用不同指标，混用必乱

```
        北极星指标（1 个）
        「这个人做这个业务，最终要变多的那个数」
                 │
    ┌────────────┼────────────┐
 一级驱动指标（3-5 个）      健康守护指标（2-4 个）
 「让北极星涨的那几个数」    「涨得太快会死的那几个数」
    │                        │
 二级诊断指标            守护指标只报警，不做决策
 「一级指标不动时，往下挖」
```

**规则**

- 一个业务阶段**只允许 1 个北极星**。有两个 = 没有。
- 一级驱动指标 ≤ 5 个。超过说明这个阶段没想清楚。
- 健康守护指标**只报警不做决策**（现金还能撑多久、退款率、投诉率）。
- 二级诊断指标**不进入周会**，只在被问到时才挖。

## 3. 指标卡模板（每个指标一张，写完才算定义完）

```yaml
指标名: 付费转化率
层级: 一级驱动
一句话定义: 看到落地页的独立访客中，7 天内完成首次付费的比例
公式: 首次付费人数 / 落地页独立访客数
分子: 支付成功且未退款的订单对应的去重用户数
分母: 同自然日内访问落地页的去重用户数（按 cookie/用户 ID 去重）
统计窗口: 自然日（Asia/Shanghai），数据延迟 T+1
排除项: 内部账号、测试订单、机器人 UA、同一用户多笔订单只计一次
数据源: 支付网关 webhook + 站点分析
归属人: 我
更新频率: 每日 09:00
基线: 2026-10-31 实际值 1.8%
目标值: 30 天内 ≥ 3.0%
预警线: 连续 3 日 < 1.2%
口径版本: v1.2（2026-10-31 生效）
历史变更:
  - v1.1 (2026-09-01) 分母从 UV 改为去重用户，数值整体下调 0.3pp
```

**必须有 `口径版本` 和 `历史变更`。** 口径一改，数值就不可比 —— 不记版本，历史数据会变成谎言。

## 4. 一人公司最小指标集（12 个，先只做这 12 个）

一个人维护不了太多指标。**指标越多，越不可能被看。**

### 收入类（3）

| 指标 | 公式 | 说明 |
|---|---|---|
| 月经常性收入 | 本月确认收入 | 一人公司初期可用「已收款总额」代替 |
| 客单价 | 收入 / 付费客户数 | 决定能不能规模化 |
| 续费率 | 到期后续费客户 / 到期客户数 | **按 cohort 算，不看总体平均** |

### 流量与转化（3）

| 指标 | 公式 | 说明 |
|---|---|---|
| 有效线索数 | 符合 ICP 且有联系方式的人数 | 不是访问量 |
| 线索→付费转化率 | 付费人数 / 有效线索数 | 分母必须是**有效线索** |
| 落地页转化率 | 付费人数 / 落地页独立访客 | 分子分母要同一时间窗 |

### 交付与质量（3）

| 指标 | 公式 | 说明 |
|---|---|---|
| 首次交付准时率 | 准时交付数 / 交付总数 | 承诺过日期的才算 |
| 返工率 | 需返工的交付数 / 交付总数 | 质量真相 |
| NPS 或推荐率 | 推荐数 - 贬损数 / 有效样本 | 小样本只看绝对数，不算比例 |

### 现金与健康（3）

| 指标 | 公式 | 说明 |
|---|---|---|
| 现金可支撑月数 | 现金余额 / 月均净支出 | **健康守护第一指标** |
| 应收账款周转天数 | 平均应收 / 日均收入 | 收不回来就危险 |
| 月度净现金流 | 流入 - 流出 | 唯一真实的"活着" |

## 5. 口径纪律（六条）

1. **一个指标只能有一个口径。** 两个口径 = 两个人吵 = 没有指标。
2. **口径写下来才算数。** 口头约定的口径不算。
3. **变更必须留痕**：改口径要写版本号、生效日期、旧口径下最近一次的值。
4. **分母必须先定义"算什么"**。"转化率""留存率""复购率"三个高频翻车点。
5. **cohort 优先于总体平均。** 总体平均会把新客和老客混在一起，掩盖真实趋势。
6. **超过 5 个一屏放不下的指标，就不是指标集，是垃圾场。**

---

## 6. 六个高频坑

| 坑 | 表现 | 修法 |
|---|---|---|
| 分母漂移 | 昨天"访客"含爬虫，今天不含 | 写死排除项 |
| 归因窗口不一致 | 30 天归因 vs 7 天归因混用 | 每个渠道固定一个窗口 |
| 幸存者偏差 | 只统计留下来的客户 | 按 cohort 记全量，包括流失 |
| 自然日 vs 时区 | 跨时区客户被算错天 | 明确写时区 |
| 退款口径 | 退款率算不算在收入里 | 明确"净收入"还是"毛收入" |
| 小样本比例 | 2/3 = 66.7% 被当成趋势 | 样本 < 30 只报绝对数 |

## 7. 工作流程

```
① 定层级      → 这个阶段哪个数是北极星？（1 个）
② 写指标卡    → 每个指标 12 个字段，缺一个不算定义完
③ 写数据源    → 这个数从哪来？谁维护？
④ 算基线      → 当前实际值是多少？（没有基线就没有目标）
⑤ 定目标与预警 → 目标值 + 预警线
⑥ 挂进看板    → 数据源接上，定期刷新
⑦ 变更留痕    → 改口径时更新版本号与历史
```

## 8. 产出物

1. **指标字典表**（Markdown 或 CSV）：一行一个指标，含 §3 全部字段
2. **指标卡**：北极星 + 一级驱动 + 健康守护，每级一页
3. **口径变更记录**：每次改动的版本、日期、原因、新旧值对比
4. **验收标准**：当前 OPC 阶段用哪些数判断"过了这一关"
